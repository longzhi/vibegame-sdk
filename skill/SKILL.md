# 做 VibePlay 游戏和小 app

掌机上跑的游戏和小 app 是同一种东西：一个 Rust 写的 wasm 模块加一个清单 `app.toml`。掌机每秒调它 60 次。每次它读按键、走一步、画一帧、发声音。
下面说「游戏」的地方，小 app 一样适用。小 app 另外要注意的，看「做小 app」一节。
你在开发机上写、跑、截图看；做好了出网页版给人玩，或者推到掌机上。

## 先装好

```sh
vibeplay doctor          # 查缺什么，缺的给出命令
```

没有 Rust（`cargo` 命令）先装 rustup：`curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`（Windows 看 https://rustup.rs）。
没有 vibeplay 命令就装：`cargo install --git https://github.com/second-state/vibeplay-sdk vibeplay-cli`。
还要 wasm32 目标：`rustup target add wasm32-unknown-unknown`。

## 先问人：游戏里的字用哪种语言

动手之前先问：「游戏里的字用英文、中文，还是两种都要？」人在要求里明说过就不再问。人用中文跟你说话，不等于游戏要中文。
现在只能选英文和中文。人要别的语言（比如日文），说清楚掌机的字和系统现在只有这两种，请他从里面选。

照答案走：

- **只要英文**：画面上的字直接写英文，不用 `lang()`。清单只写 `title`，把 `title_zh` 那行删掉。只截英文的图。
- **只要中文**：画面上的字直接写中文，不用 `lang()`。清单的 `title` 写中文名，`title_zh` 那行删掉。只截图看中文。
  中文字 12 像素宽，是英文的两倍，一行放不下就换行或者改短。
- **两种都要**：画面上的字都写两种，用 `lang().pick`（见下面「语言」）。清单 `title` 写英文名，`title_zh` 写中文名。英文、中文各截一套。

模板（`vibeplay new`）是两种都要的写法。只要一种时，把模板里的 `lang().pick(英文, 中文)` 换成那一种的字。

## 一个游戏从头到尾

```sh
vibeplay new star-catch --title "Star Catch"     # 从模板起一个：十字键走、捡星星、计时、存最高分
cd star-catch
vibeplay run                                # 开窗口玩（人玩）
vibeplay shot --frames 5,120 --input s.txt  # 你看：跑到第 5、120 帧各存一张 PNG
vibeplay run --headless --frames 300 --input s.txt   # 你听：印出每一个音调
vibeplay web                                # dist/star-catch.html：一个文件，浏览器里就能玩
vibeplay pack                               # dist/star-catch.vp：拷进 TF 卡的「游戏」目录
vibeplay pair 192.168.1.23 && vibeplay push # 推到掌机上直接开（掌机要开开发者模式）
```

`vibeplay help` 看全部命令和选项。

`new --title` 换清单的 `title` 和标题画面上的名字。还要自己做三件事：
- 名字照第一步定的语言写：两种都要时打开 `app.toml` 里 `title_zh` 那行注释；只要中文时 `title` 直接写中文名。
- 代码里别的字（「PRESS START」、计分）照新游戏改。
- 模板的封面是通用的一张（夜空、星星、小人），换成自己游戏的。

做小 app 也从模板起，把捡星星的部分换掉；或者从最像的那个小 app 样板改（见「改别人的游戏」，比如 `vibeplay remix scorepad my-score`）。

## 自己验：一定要看截图

你看不到窗口。改了画面就截几张图，用读图片的工具看：

- 字清楚吗？漏了的字会画成空心框。
- 颜色对吗？东西在该在的地方吗？
- 标题、开玩、过关、输了，每个画面都截一张。两种语言都要时，英文（默认）和中文（`--lang zh`）各截一套；只要一种就截那一种。

按键脚本一行一条：`0-29 right` 是前 30 帧按着右，`30 a` 是第 30 帧按 A。帧从 0 数，`#` 后面是注释。
键：`up down left right a b x y l1 r1 start select`。`shot --crop x,y,w,h` 只存一块。
看小精灵的细节（眼睛、几个像素的东西），用 `--crop` 框住它再加 `--scale 6`：整屏 3 倍的图看不清。
`shot --out a.png` 给一个帧号时就存成 `a.png`，给几个帧号时存成 `a-5.png`、`a-120.png`。
`--data 目录` 给存档一个地方：`run` 开窗口时默认是游戏目录下的 `save/`。
`--headless` 和 `shot` 不给 `--data` 就存不了（`vibeplay::save` 回 false）。要截「标题上有最高分」这种图，给它一个目录。
`save("best", 字节)` 就是目录里一个叫 `best` 的文件，内容原样。跑的时候会改写这个目录：要每次从同一份存档开始，先拷一份新的再跑。
无头跑时 `tone_wav` 印成「帧 N 录音 毫秒=…」，别的印成「帧 N 音调 声道=… 频率=…」。

规则用单元测试验：`cargo test`。测试里直接造 `Game::default()`，`keys.set(位)`，再调 `step()`，看状态。
- **每帧都 `set` 一次**：按住就每帧 set 同一个位。同一个键要按两下，中间要有一帧 `set(0)`，不然 `pressed` 认不出第二下。
- 测试里的存档、音调、语言是一个线程一份，测试一起跑也不串。要干净的存档，开头 `vibeplay::erase(名字)`。
  `vibeplay::full::native::take_tones()` 取出这个线程发过的音调。
想知道第几帧起跳正好，在测试里循环试，试出来写进脚本。

## 做小 app

除了游戏，掌机还适合几个按键就能用、不用打字的小东西。样板里每类有一个（见「抄样板」）：

- 给孩子的：口算、单词卡。答案让人从几个里选（左、上、右各一个），不要让人输数字。
- 电子宠物：随真的时间饿、困、长大。
- 桌面摆件：时钟、鱼缸、相框。掌机竖在键盘边上看。
- 聚会用的：记分板、骰子、抽签、倒计时。
- 音乐玩具：节拍器、音序器、把按键当琴。

清单里写 `kind = "app"`，集市上就放在「应用」那一栏。

不适合的，先跟人说清楚：
- 要打很多字的（记事、聊天）：掌机没有键盘，也没有触摸屏和麦克风。
- 要联网的（天气、股价）：先不做。联网要在清单写 `hosts`，样板都不联网。

### 按键和画面

- **按键的意思全程一样**：十字键选，A 确定，B 返回或撤销，START 开始、暂停或开菜单，SELECT 做一件次要的事（掷骰子、换一套）。
- **底下一行小字写这一屏能按什么**。摆件（时钟这种不用按的）例外：只在打开时和按键后出几秒。
- **字要大、要少**：屏只有 240×160，一屏只放一件主要的事。
  - 大数字可以 `FONT.sprite("12", 颜色).scaled(3)`。字的笔画只在 12 像素高的字格里第 2 到 9 行，放大后上面空出一截，竖着居中要自己算。
  - 自带字的 0 中间有一道斜线。给孩子看的、要隔着桌子看的数字，自己画一套点阵数字（`mathstar`、`deskclock` 里有）。
- **按住连加**（记分、调速度）：库里没有，自己数帧。先动一次，按住 24 帧后每 8 帧动一次，越久越快。抄 `scorepad`。
- **主画面上叠一个菜单**：用一个 `mode` 枚举分开「主画面」「菜单」「确认框」，`step` 和 `draw` 都先看 mode。抄 `scorepad`。

### 时间

- **`vibeplay::now()`** 回本地时间 `Time { unix, year, month, day, weekday, hour, minute, second, tz_offset }`。`weekday` 0 是星期一。每帧都能调。别用 `std::time`：wasm 里没有钟。
- **只到秒**。冒号每秒闪一次这种，自己记这一秒从第几帧开始。
- **规则收 `Time`，不自己读钟**：只在 `every` 里调一次 `now()`，传给 `g.step(&now)`。算状态的函数收 `&Time`（要钟点用 `hour`，算过了多久用 `unix`）。
  测试里用 `Time::at(unix, 时区偏移)` 造一个时间，`t.plus(8 * 3600)` 是 8 小时以后。开发机上 `now()` 读真钟，测试里定不住，所以别在规则里调它。
- **过了多久**：存下上次的 `unix`，下次相减。
  - 每帧都减的话，一帧还不到一秒，零头会被扔掉。按整分钟（或整秒）算，存的时间只往前推用掉的那部分。
  - 合盖、关机、退出时 app 不跑，回来时一次补上。补的时候设上限（比如最多 12 小时），钟往回拨时什么都不做。抄 `pixelpup` 的 `pet.rs`。
- **截图定住钟**：`vibeplay shot --time 2026-11-14T07:30:00 ...`。以后每 60 帧走一秒，同样的按键每次截出来一样。
  - 白天、夜里、过零点，各用一个 `--time` 截一张。
  - 「离开了很久」：同一个 `--data` 目录，先用早的 `--time` 跑一次，再用晚的 `--time` 截图。不用手算 unix 秒。
- **掌机上 5 分钟没人按键，屏会调暗**（夜里更暗）。时钟这种摆件照常走，只是暗一些。按一下键就亮。

### 存档

- **状态一变就存**：加了分、喂了饭、改了格子。按住连加时隔半秒存一次，松手再存。会随时间变的（宠物），每走一步存一次。
- 不要每帧都存，也不要只在退出时存：没电、合盖太久时 app 来不及收尾。
- 存档坏了（版本不对、长度不对）就当没有，从头开始，别 panic。

### 声音

- 同一个声道上，新的音调顶掉正在响的。军鼓和踩镲都用噪声的话，同一步只能响一个，挑一个或者错开。
- `tone(声道, 0, 0, 0)`（毫秒是 0）是停掉这个声道。
- 噪声的「频率」是噪声的时钟，不是音高：越高越沙。鼓大约这样：底鼓用三角波 150 Hz 往 55 Hz 滑，军鼓用噪声 6000，踩镲用噪声 16000。
- 滑音、渐弱：库里没有包络，每帧重发一次 `tone`，换频率或音量。
- `music.play` 会停掉正在放的曲子。几个音的提示曲用一首不循环的 `Song`；一个音的提示用 `music.sfx`。
- **按速度（BPM）走的**：`Song` 一格只能是整数帧，120 BPM 的半拍是 15 帧，十六分音符是 7.5 帧放不下。自己攒余数：每帧加 `bpm × 每拍几步`，满 3600 走一步。抄 `beatbox`。
- `full::hz(音符号)` 把 MIDI 音符号换成频率。

## 写游戏用的东西（`vibeplay::full`）

下面是常用的。全部的函数看源码：`vibeplay::full` 就是 qingos-sdk 的 `qapp::full`。
游戏编过一次，源码就在 `~/.cargo/git/checkouts/qingos-sdk-*/<提交>/qapp/src/full.rs` 和 `full/` 下面。
有几份时看游戏的 `Cargo.lock` 里 qingos-sdk 那一行的提交。

- **画面** `Frame`：240×160，一个像素一个字节，是调色板的一格。调色板 256 格，`frame.palette[格] = [r, g, b]`。
  `clear`、`set`、`rect`、`blit(&精灵, x, y, 左右翻)`、`frame_rect`。每帧最后 `frame.show()` 一次。
- **按键** `Keys`：每帧开头 `keys.read()` 一次。`held`（按着）、`pressed`（这一帧刚按下）、`released`。
  键是 `key::UP`、`DOWN`、`LEFT`、`RIGHT`、`A`、`B`、`X`、`Y`、`L1`、`R1`、`START`、`SELECT`。菜单键归掌机，游戏收不到。
- **精灵** `Sprite::art(&["..yy..", ".yooy."], &[('y', 11), ('o', 13)])`：字符画，`.` 和颜色格 0 透明。
  `scaled(k)` 放大，`recolor(&[(旧, 新)])` 换色（被打中闪白）。换成 0 就是透明。
- **地图** `TileMap::parse(&行, 16, |字符| 格)`：一格 16 像素，一屏 15×10 格。`draw(&mut frame, &图块, &cam)`；`hits(x, y, w, h, |格| 实心?)` 做碰撞。
- **镜头** `Camera::follow(x, y, 世界宽, 世界高)`：主角走出画面中间那块才跟。`to_screen`、`sees`。
- **字** `vibeplay::FONT`：12 像素高，英文和常用中文都有。`frame.text(&FONT, x, y, "第 1 关", 颜色)`、`text_center`、`text_outlined`（压在花背景上加描边）。
  大字：`FONT.sprite("标题", 颜色).scaled(3)` 再 `blit`。
  有的符号：`← ↑ → ↓ ★ ▲`（箭头 12 像素宽）。没有的：`▶ ♥`，要用就自己画成精灵。不确定就截图看，漏了的字是空心框。
- **声音**：四个声道。`Square1`、`Square2` 是方波，`Triangle` 是三角波，`Noise` 是噪声（频率越高越沙）。
  `tone(声道, 频率, 毫秒, 音量)`。短录音：`tone_wav(&wav)`，16 位 PCM，最长 2 秒，和声道混着响。
- **音乐**：`Track::parse(声道, 音量, "C4 E4 G4:2 r A#3")`，`Song::new(一格几帧, 循环, 几轨)`，`music.play(song)`，每帧 `music.tick()`。
  音效 `music.sfx(声道, 频率, 毫秒, 音量)`：音乐在那个声道上让一会儿，响完接上。
- **语言** `vibeplay::full::lang()`：系统是英文还是中文，默认英文。只在人要两种语言时用（见「先问人」）。画面上的字写两种：`lang().pick("GAME OVER", "游戏结束")`。
  每次出字都问，别存进游戏的状态里：人能在暂停时换语言。英文字 6 像素宽，中文 12 像素，两种都要截图看放不放得下。
  清单 `title` 写英文名，`title_zh` 写中文名。测试里用 `vibeplay::full::native::set_lang(Lang::Zh)` 换（只换这个线程）。
- **时间**：`vibeplay::now()`，见「做小 app」。
- **存档**：`vibeplay::save("best", 字节)`、`vibeplay::load("best")`、`vibeplay::erase`。存在掌机上这个游戏自己的地方，浏览器里存在本机。
- **日志**：`vibeplay::log("…")`，`vibeplay run` 印在终端里。

## 骨架

模板就是这个样子。状态全放在一个 `Game` 里：

```rust
static GAME: Mutex<Option<Game>> = Mutex::new(None);
vibeplay::main!(|app| {
    app.every(|| {
        let mut g = GAME.lock().unwrap();
        let g = g.get_or_insert_with(Game::default);
        g.keys.read();
        g.step();   // 动、算碰撞、发声
        g.draw();   // 画
        g.frame.show();
    });
});
```

看时间的小 app，每帧先读一次钟，传进去：

```rust
    app.every(|| {
        let now = vibeplay::now();
        let mut g = GAME.lock().unwrap();
        let g = g.get_or_insert_with(|| Game::load(&now));   // 读存档，补上没开的时候过了多久
        g.keys.read();
        g.step(&now);
        g.draw(&now);
        g.frame.show();
    });
```

## 约定

- **清单** `app.toml`：`name` 是英文小写，和目录名一样。`screen = "full"`、`rate_hz = 60` 不改。
  `cover` 是掌机的家上的封面，`assets/` 下一张 96×80 的 PNG。画一张，别直接截图。封面上不写名字：家上封面底下有名字，跟着系统的语言换。
  样板的封面是 Python 加 Pillow（`pip install pillow`）一个像素一个像素画的：游戏的在 `tools/game-covers.py`，小 app 的在 `tools/covers/<名字>.py`。
  `tools/covers/` 下每个都是独立的一个文件，拷一个改就行。封面上的数字、表盘算图案，可以画。
- **调色板**：格子编号起名字（`const INK: u8 = 1;`），画的时候只写名字。第 0 格当背景。
- **版本**：算数的是 `app.toml` 的 `version`（集市、掌机看它）。`Cargo.toml` 的版本不管。
- **位置**用整数（比如 1/16 像素），不用浮点。随机数自己写，开局从同一个数开始。这样同样的按键每次跑出来一样，截图和测试才稳。
  可是每次打开都出一样的题、一样的关就没意思了：把存下的局数、在标题上等了几帧掺进种子。同样的按键还是跑出一样的结果。

只对游戏的：
- **主角** 16×16 左右。动画是几张精灵换着画：走两张，跳一张。
- **声音**：旋律放 `Square1`，低音放 `Triangle`，鼓点放 `Noise`，音效放 `Square2` 或用 `sfx` 借一个声道。跳、捡东西、打中各用不一样的高低。
  爆炸这种声音：代码里生成一小段噪声慢慢变小的 WAV，`tone_wav` 放。库里没有现成的，抄 `skyfire` 的 `boom_wav`。

## 抄样板

https://github.com/second-state/vibeplay-sdk/tree/main/examples 有四款做完的游戏，要什么抄什么。
游戏编过一次，样板也在本机：`~/.cargo/git/checkouts/vibeplay-sdk-*/<提交>/examples/`，不上网也能读。

- `courier`《疾风邮差》：横版跳跃。地图块、镜头跟着走、重力、踩敌人、大怪。
- `thunder`《雷霆突击》：横版射击。子弹、八个方向打、一屏很多东西、音乐和爆炸声一起响。
- `skyfire`《烈空战机》：竖版飞机射击。地图往上卷、出敌脚本、成片的子弹、分几块打的大怪、炸弹。
- `ironcamp`《铁壳守营》：俯视坦克战。一格一格的地图、能打碎的墙、敌人的路线、二十关。

小 app 的样板：

- `mathstar`《口算星星》：给孩子的口算。三选一答题、答对给星星、两档难度、存最好成绩。
- `pixelpup`《像素小狗》：电子宠物。随真的时间饿、夜里睡觉、喂饭、遛狗、补上没开的时候过了多久。
- `deskclock`《桌面时钟》：大字时钟和鱼缸。读时间、12 和 24 小时制、记住设置。
- `scorepad`《记分板》：聚会记分。几个人、加减分、按住连加、换人、存着不丢。
- `beatbox`《节拍盒》：八步的音序器。格子里开关音、四个声道、调速度、存下节奏。

## 原创

- 做「那个年代的样子」，不做那个年代的某一款。小 app 也一样：电子宠物做自己的宠物，不照某一款的样子和名字做。角色、关卡、画面、音乐都自己做。
- 别人要你照某款老游戏原样做，先说清楚这一条，再给一个原创的版本。
- 像素画用字符画自己画，不从网上拿图。曲子自己写，别哼一首听过的。

## 推到掌机

- 掌机上打开开发者模式（设置 → 系统）。屏幕上有地址和口令。
- `vibeplay pair <地址>` 输口令，配一次就行。`vibeplay push` 打包、推过去、直接打开。`--watch` 一改就再推。
- 同一个游戏再推，直接换掉，存档留着。新游戏掌机上会问一次装不装，要人按 A。
- 不用 Wi‑Fi：`vibeplay pack` 出的 `.vp` 拷进 TF 卡的「游戏」目录，插上掌机开机就装。

## 发到集市

集市是大家发游戏、装别人的游戏的地方。发了马上上架，别人的掌机打开集市就能装。

- 第一次要人做两件事，agent 替不了：`vibeplay login`（在浏览器里输码登录 GitHub），第一次 `publish` 时在终端里答应条款（输 yes）。
- 清单要有 `description`（集市上的一两句介绍，可以加 `description_zh`）和 `cover`。名字不能和预装的游戏一样。
- 清单写 `langs = ["en"]` 或 `["en", "zh"]`：游戏里的字用哪几种语言。只能是 en、zh。
- 应用（不是游戏的）在清单写 `kind = "app"`：集市分「游戏」「应用」两栏。不写就是游戏。
- `vibeplay publish` 先在这台电脑上查清单、不开窗口跑 600 帧、截三张图，再打包上传。出错就照它说的改。
- 每发一次，`version` 要往上加（0.1.0 → 0.1.1）。发错了不能退回，发一个更大的版本。
- `vibeplay status` 看上没上架、装了几次、最近没过的原因。`vibeplay unpublish <名字>` 下架，已经装了的掌机照常用。
- 集市不收：要 mcu 的、带人格的、要网却没写 `hosts` 的。一个账号一天最多发 20 次。
- 公开源码是作者自己的事：人说了要公开，才加 `--source`。不要替人决定。
  - 只收 `Cargo.toml`、`Cargo.lock`、`app.toml`、`src/`、`assets/`，压缩后最多 2 MB。不收隐藏文件，不收像 key 的字符串。
  - 每个游戏第一次公开时，要人在终端里答应（输 yes），agent 替不了。以后的版本只列出文件。
  - 开源协议默认 MIT。人要别的，在清单的 `[app]` 里写 `license = "Apache-2.0"` 这样的 SPDX 写法。

## 改别人的游戏

集市上公开了源码的游戏，谁都能改成自己的。人说「把集市上的 skyfire 改成……」，照这样做：

- `vibeplay remix skyfire <新名字>`：下载 skyfire 最新那一版的源码，起一个新游戏。目录名就是新名字，不写是 `skyfire-remix`。
  作者没有公开源码的游戏改不了，就跟人说。
- 新游戏的名字、版本（0.1.0）已经换好，清单里记了 `from = "skyfire@0.1.1"`。不要删这一行：集市靠它写出「改自 skyfire」。
- 开源协议照原来的（清单里的 `license`）。不要改成别的，除非人说了，而且原来的开源协议允许。
- 照人说的改，`vibeplay run`、`shot` 自己验，`push` 推到掌机给人玩。
- 人说要发，再 `publish`。发之前把 `title`、`description` 改成新游戏的，封面最好也换：不然集市上有两个一样名字的游戏。
